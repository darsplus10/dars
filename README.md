# 📘 DarsPlus — سجل الصف الدراسي

> أحد منتجات **أنظمة تسنيم المحوسبة — Tasnim Systems**

تطبيق ويب لإدارة صف دراسي: رفع قائمة الطلاب، تسجيل **الحضور والغياب والتأخر**، وتوثيق الحصص.
**تاريخ الحصة يُملأ تلقائياً من نظام الجهاز** ويمكن تغييره يدوياً لتوثيق حصة سابقة.

**البيانات تُحفظ على خادم الموقع نفسه** عبر Netlify Blobs — تفتح الرابط من أي جهاز فتجد بياناتك.

---

## التقنية

| الطبقة | الأداة | لماذا |
|---|---|---|
| الواجهة | HTML + CSS + JavaScript خالص | بلا إطار عمل وبلا خطوة بناء — Netlify يقدّم ملفات ثابتة فقط، ولا يشغّل PHP |
| الخادم | Netlify Function واحدة (`netlify/functions/data.mjs`) | نقطة واحدة للقراءة والكتابة |
| التخزين | Netlify Blobs | مدمج في Netlify — بلا حساب خارجي ولا إعداد قاعدة بيانات |

## 🚀 النشر على Netlify

الدالة تحتاج حزمة `@netlify/blobs`، ولذلك **يجب أن ينشر Netlify الموقع من مستودع Git**
حتى ينفّذ `npm install`. الرفع بالسحب والإفلات لا يثبّت الحزم.

### 1. ارفع المشروع إلى GitHub

المستودع المحلي مهيّأ مسبقاً (فرع `main` مع أول commit). بقي إنشاء المستودع على GitHub وربطه:

1. من <https://github.com/new> أنشئ مستودعاً باسم `darsplus`، واجعله **Private** (خاص)،
   ولا تُضف README ولا `.gitignore` ولا ترخيصاً — كلها موجودة هنا.
2. ثم من داخل مجلد المشروع:

```bash
git remote add origin https://github.com/<اسم-المستخدم>/darsplus.git
git push -u origin main
```

بعد ذلك كل تعديل يُرفع هكذا، ويعيد Netlify النشر تلقائياً:

```bash
git add .
git commit -m "وصف التعديل"
git push
```

> `.gitignore` يمنع رفع `backups/` وأي ملف Excel أو CSV أو `.env` — فلا تصل أسماء الطلاب
> ولا كلمات المرور إلى المستودع. تأكّد قبل كل `git push` بالأمر `git status`.

### 2. اربطه بـ Netlify

في لوحة Netlify: `Add new site` ← `Import an existing project` ← اختر المستودع.

الإعدادات تُقرأ تلقائياً من [`netlify.toml`](netlify.toml):

| الحقل | القيمة |
|---|---|
| Build command | *(فارغ)* |
| Publish directory | `.` |
| Functions directory | `netlify/functions` |

> إذا كان مجلد المشروع داخل مستودع أكبر، اضبط **Base directory** على اسم ذلك المجلد.

### 3. اضبط كلمة المرور *(موصى به بشدة)*

`Site configuration` ← `Environment variables` ← `Add a variable`:

| Key | Value |
|---|---|
| `APP_PASSWORD` | **نفس كلمة المرور المستعملة في صفحة الدخول** |

ثم أعد النشر (`Deploys` ← `Trigger deploy`).

⚠️ **بدون هذا المتغيّر، أي شخص يملك الرابط يستطيع قراءة أسماء طلابك وتعديل السجل.**

### 4. تحديث موقع مرفوع سابقاً بالسحب والإفلات

الموقع القديم لا يحتوي الدالة. من لوحة Netlify:
`Site configuration` ← `Build & deploy` ← `Link to a Git repository`، ثم اتبع الخطوتين 2 و 3.
الرابط `*.netlify.app` يبقى كما هو.

## كيف يعمل الحفظ

بطاقات ملف الصف وأحداثه تُحفظ **على خادم الموقع** مثل باقي السجل تماماً: كل تعديل يُرفع
إلى `PUT /api/data` خلال أقل من ثانية، ويظهر في أي جهاز تفتح منه الرابط. التخزين المحلي
في المتصفح ذاكرة مؤقتة فقط — لو مسحته عاد كل شيء من الخادم عند أول فتح.

> يتطلّب أن يكون الموقع منشوراً على Netlify مع الدالة. عند التشغيل المحلي البسيط
> (`python -m http.server`) لا توجد دالة، فيعمل التطبيق بالتخزين المحلي ويُظهر ذلك
> في مؤشّر الحالة أعلى الصفحة وفي سطر داخل صفحات ملف الصف.


1. كل تعديل يُحفظ فوراً في `localStorage` كذاكرة مؤقتة، فلا تنتظر الشبكة.
2. بعد 0.7 ثانية من آخر تعديل تُرفع البيانات كاملة إلى `PUT /api/data`.
3. عند فتح الموقع تُجلب البيانات من `GET /api/data` وتحلّ محل النسخة المحلية.
4. مؤشر الحالة في الأعلى يعرض: *جارٍ الحفظ… / محفوظ على الموقع / تعذّر الاتصال*.
5. لو عدّلت من جهازين في وقت واحد، يرفض الخادم الكتابة الثانية (409) ويسألك أي نسخة تعتمد.

### واجهة الخادم

| الطلب | الوظيفة |
|---|---|
| `GET /api/ping` | هل الخادم متاح؟ وهل هو محمي؟ (بلا مصادقة، لا يكشف بيانات) |
| `GET /api/data` | جلب كل البيانات |
| `PUT /api/data` | حفظ كل البيانات — يرفض الكتابة فوق تعديل أحدث إلا بـ `force` |

كلمة المرور تُرسل في ترويسة `x-app-key` بترميز base64 (لأن ترويسات HTTP لا تقبل إلا ASCII،
وهذا ما يجعل كلمات المرور العربية تعمل).

## 🔑 صفحة الدخول — وماذا تحمي فعلاً

الدخول بـ **اسم مستخدم + كلمة مرور**. اسم المستخدم مكتوب في `AUTH_USER`، وكلمة المرور
محفوظة كبصمة SHA-256 في `AUTH_HASH` بدل نصّها الصريح.

عند الدخول تُرسَل كلمة المرور نفسها إلى `/api/data` في ترويسة `x-app-key`، فإن كانت
`APP_PASSWORD` مضبوطة على القيمة نفسها صار المنع **على الخادم**: لا بيانات تُجلب بدونها.

⚠️ **بدون `APP_PASSWORD` الصفحة حاجز شكلي فقط.** فحص اسم المستخدم وكلمة المرور يجري
داخل المتصفح، ومن يفتح مصدر الصفحة يرى `AUTH_HASH` ويستطيع تخطّي الشاشة أو كسر بصمة
كلمة مرور قصيرة. البصمة تمنع القراءة بالعين، لا أكثر. الحماية الحقيقية على الخادم.

## 🔒 أين تُحفظ بيانات الطلاب الشخصية؟

بطاقات «ملف الصف» تحتوي أرقام هوية وهواتف وبيانات أهالٍ، ولذلك **لا تُوضع داخل ملفات الموقع**.
تُستورد من ملف Excel على جهازك، فتُحفظ مع باقي بيانات السجل وتنتقل إلى الخادم عبر `PUT /api/data`
وهي الطريق الوحيد الذي يحرسه `APP_PASSWORD`.

⚠️ أي ملف يوضع داخل المستودع (js أو json أو xlsx) يُقدَّم للجميع بلا كلمة مرور —
`APP_PASSWORD` يحمي `/api/*` فقط، لا الملفات الثابتة. لذلك:

1. **اضبط `APP_PASSWORD`** قبل إدخال بيانات الطلاب الشخصية (الخطوة 3 أعلاه)، وليكن
   بنفس قيمة كلمة مرور صفحة الدخول — عندها ترسلها الصفحة إلى الخادم فتصير الحماية حقيقية.
2. لا تضع ملف الأسماء داخل مجلد المشروع. مكانه `backups/` المستثنى من المستودع والنشر، أو خارج المشروع أصلاً.

## ملاحظات وحدود

- **كلمة مرور واحدة للجميع** — لا يوجد نظام حسابات منفصلة لكل معلّم. من يعرفها يرى كل الصفوف.
- **البيانات تُرسل كاملة** في كل حفظ. مناسب لعشرات الصفوف؛ لو كبر السجل كثيراً فالأفضل الانتقال
  إلى قاعدة بيانات حقيقية (Supabase / Neon) مع حفظ جزئي.
- **تصدير JSON** من صفحة «التخزين والنسخ الاحتياطي» يبقى متاحاً كنسخة إضافية خارج الخادم.
- **مجلد `backups/`** لحفظ هذه النسخ على جهازك. يحتوي أسماء طلاب، لذلك هو مستثنى في `.gitignore`
  فلا يدخل المستودع ولا يصل إلى Netlify، ومع ذلك تمنع قاعدة في `netlify.toml` تقديمه لو وصل بأي طريقة.
  لاستعادة نسخة: صفحة «النسخ الاحتياطي» ← «استيراد (استبدال)».
- بدون خادم (تشغيل محلي أو ملف مفتوح مباشرة) يعمل التطبيق بالتخزين المحلي فقط، ويظهر ذلك في المؤشر.
